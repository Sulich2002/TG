# Личный тренер

Вход: «Сегодня → Обсудить с тренером» или «Прогресс → Тренер». У каждого аккаунта свой разговор, цель и разрешение на передачу данных. Можно выбрать тренировку за 7/30 дней, открыть обсуждение из истории, спросить о сегодняшней нагрузке или разобрать неделю. Цель поддерживает свободное описание подготовки и дату события; тренер может задавать уточняющие вопросы. План обсуждается в чате, без автоматической записи тренировок или начисления XP.

## Подключение владельцем

Сначала обновить существующий коннектор на сервере:

```sh
curl -fsSL https://sulich2002.github.io/TG/garmin-setup.sh -o /tmp/tg-garmin-update.sh && bash /tmp/tg-garmin-update.sh --update
```

В приложении войти в аккаунт группы; если его ещё нет — создать через «Прогресс → Друзья» с существующим подключением Garmin владельца. В «Тренер → Подключить ИИ» открыть https://console.groq.com/keys, создать ключ в бесплатном аккаунте без подключённой оплаты и вставить **в приложение**, не в переписку. Тариф и доступность в регионе проверяются в аккаунте Groq. Актуальные ограничения: https://console.groq.com/docs/rate-limits. Программа не может проверить платёжные настройки аккаунта провайдера и не гарантирует неизменность его бесплатного тарифа.

Подключение проверяет список доступных моделей через Groq API. Предпочтение: `llama-3.3-70b-versatile`, затем `llama-3.1-8b-instant`, затем `openai/gpt-oss-20b`; используется первая реально доступная модель. Ключ хранится в серверной SQLite с правами 0600, не попадает в браузерное хранилище, ответы API, контекст модели или публикуемый сайт. Ключ общий для группы, но каждый участник видит только свой разговор. Владелец может отключить провайдера и удалить ключ; существующий разговор сохраняется.

После подключения каждый участник открывает «Твоя цель → Изменить», описывает цель и разрешает передачу своего контекста. Открытие чата, выбор тренировки и сохранение цели не отправляют тренировочные данные провайдеру. Передача происходит по отправке сообщения. Можно отозвать разрешение в тех же настройках.

## Что получает модель

- Профиль пользователя, цель и дата события, последние сообщения его разговора.
- Записи занятий за последние 30 календарных дней, выбранное занятие подробнее; агрегаты нагрузки за последние 7 календарных дней, включая сегодня.
- Зафиксированные группы мышц/подходы зала, домашние повторения, известные время/дистанцию, средний/максимальный пульс, время в движении и с паузами, темп для импортированных записей, когда эти поля есть.
- Доступные сон, пульс в покое, шаги, стресс, Body Battery и HRV за неделю, даты обновления и ошибки синхронизации. Сегодня помечено как незавершённый день. Пропуски остаются неизвестными, действительные нули сохраняются. Показатели с ошибкой загрузки исключаются.

В контекст входят текущие локальные записи пользователя, даже если отправка дневника в облако ещё не завершилась. Сервер валидирует их по тем же правилам, что и дневник; это не изменяет серверную копию дневника. Импортированное занятие Garmin не дублируется повторным чтением часов. Похожие на ручную запись неимпортированные сеансы помечены как возможные дубли и исключены из числа занятий недели. Неизвестные группы мышц сохраняются неизвестными. Отсутствие записи не считается отсутствием тренировки.

Не передаются пароли, API-ключи, Garmin-сессии, чужие записи, вся исходная выгрузка Garmin и массивы подробных пульсовых измерений. Список занятий и история разговора ограничены по объёму, полные численные итоги недели считаются до сокращения списка. Модель не имеет инструментов для доступа к серверу или изменения данных. Ответы могут ошибаться; форматирование выводится безопасным текстом без исполнения HTML.

## Ограничения и хранение

20 обращений на человека и 100 на сервер за московские сутки, не более одного одновременно. Внешняя бесплатная квота Groq может закончиться раньше: приложение показывает ошибку и не переключается на платный API. Неудачные обращения тоже учитываются в собственном лимите. После сетевого сбоя повтор того же сообщения использует прежний идентификатор, чтобы не получить второй ответ, если первый уже сохранён. Изменения разговора с другого устройства требуют обновления истории; введённый текст сохраняется в поле.

Последние 50 пар сообщений сохраняются в личном аккаунте на сервере и доступны с другого устройства. В модель отправляются только последние четыре пары в сокращённом виде. Очистка удаляет серверную историю, сохраняя цель и дневник; она не удаляет данные, уже обработанные внешним провайдером. Условия использования/хранения данных у Groq зависят от его настроек и тарифа.

На VDS не запускается локальная языковая модель: вычисления выполняет внешний API, дополнительной зависимости Python нет. VPN и настройки портов не меняются.

## Проверка

Node-тест проверяет выбор актуальных локальных и Garmin-записей с календарными границами. Python-тесты проверяют контекст, известные группы/подходы, выбранный пульс, пропуски/нули, дубли, доступ владельца, явное разрешение, изоляцию чатов, повтор сообщения, конфликты, квоты, очистку, HTTP Origin/авторизацию и отсутствие ключа в API/контексте. Браузерная проверка использует тестовый провайдер и синтетические записи. Настоящий ответ Groq необходимо проверить после ввода действующего ключа на сервере владельца; действующего ключа в облачной среде нет. Официальные страницы тарифов недоступны из текущего облачного прокси, поэтому точные актуальные численные квоты Groq не заявляются. Формат API сверялся с доступным официальным [Groq Python SDK](https://github.com/groq/groq-python).
