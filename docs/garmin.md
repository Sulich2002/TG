# Garmin: состояние и следующий шаг

Подключение ещё не реализовано. Сайт на GitHub Pages остаётся статическим локальным дневником; кнопки, создающей видимость работающей синхронизации, нет.

Пользователь хочет автоматический импорт из Garmin Connect с пульсом, дистанцией, временем и темпом, допускает прямой вход, располагает сервером HostVDS во Франции с работающим VPN. Адрес сервера получен отдельно; SSH-доступ и авторизация Garmin пока отсутствуют. Проверка стандартного SSH-порта 22 из облачной среды завершилась Connection refused до аутентификации. Запрошен порт или строка подключения из панели HostVDS. IP не хранится в публичном репозитории. Не просить пароли/ключи через чат и не коммитить их.

## Проверенный кандидат

[python-garminconnect](https://github.com/cyberjunky/python-garminconnect), MIT. 15 октября 2026 изучены README, pyproject.toml и исходный garminconnect/__init__.py из публичного репозитория. Текущая документация описывает прямой SSO-вход, MFA callback, сохранение и обновление токенов. Методы `get_activities`, `get_activity`, `get_activity_details`, `get_activity_hr_in_timezones`, `get_activity_exercise_sets`, `download_activity` позволяют получать сводки, подробности и файлы; фактическая полнота зависит от конкретной записи Garmin. В частности, отсутствие записанного пульса нельзя заменять вымышленными значениями. Для текущего исходного дерева требуется Python 3.12+.

Это бесплатная библиотека неофициального доступа к сервисам Garmin, а не официальный партнёрский API. Изменения входа Garmin могут нарушать работу. Вход на реальном аккаунте ещё не проверен. README сообщает об отказе от garth начиная с версии 0.3.0, поэтому не копировать устаревшие инструкции OAuth1/garth. Перед установкой выбрать актуальный стабильный релиз, зафиксировать зависимости и проверить вход в нём.

Официальные страницы Garmin Developer, HostVDS и публичная t.me-страница бота были недоступны из облачной среды (egress proxy: 403). Их текущее содержимое и внутренний способ работы @fizkult_ai_bot не проверены. Не выдавать это за неисправность сервисов.

## Предполагаемая реализация после получения доступа

1. Прочитать конфигурацию сервера: ОС, ресурсы, существующие сервисы/контейнеры, занятые порты, firewall, способ работы VPN. Не выводить конфиги с ключами и не менять VPN. Подключение — существующая защищённая привязка SSH или ограниченный отдельный ключ.
2. Выделить отдельного пользователя/каталог/сервис синхронизации. Серверная часть нужна для долговременной сессии Garmin, планировщика, данных и защищённого API приложения. GitHub Pages не исполняет такой код. Не использовать Actions как хранилище персональных тренировок.
3. Настроить HTTPS и авторизацию владельца до открытия API наружу; определить домен и схему входа (проверенные сервером Telegram initData требуют собственного бота, который ещё не настроен). Не считать IP или имя из initDataUnsafe авторизацией. Публичную кнопку ввода Garmin-пароля до этого не добавлять.
4. Первый вход передаёт логин/пароль и при необходимости MFA непосредственно в Garmin через серверный клиент. Сохранить сессию с ограниченными правами вне web-root; пароль после входа не сохранять. Сессию тоже считать секретом. TLS-проверку не отключать. Не записывать секреты или подробные ответы аккаунта в журналы.
5. Импортировать ограниченный начальный диапазон, затем периодически проверять новые/изменённые активности с умеренным интервалом и backoff. Ключ импорта — пара пользователя и Garmin activity ID; повторные опросы не создают дублей тренировок/опыта/достижений. Перед импортом старой истории показать пользователю диапазон и ожидаемый объём. Учесть уже вручную записанные занятия и явное подтверждение возможного дубля.
6. Хранить оригинальные единицы и преобразовывать метры → км, секунды → минуты; различать elapsed/moving time. Нормализовать локальную дату активности, нули/отсутствующие значения пульса и тип спорта. Не превращать велозаезд в пробежку. Не рассчитывать зал по отсутствующим сетам/весам. Обновление активности должно обновлять ту же запись с явно определённой политикой XP.
7. Подключить приложение к API, сохранить существующий локальный дневник, реализовать отключение и обработку истёкшей сессии. Сначала проверить реальный импорт одной пробежки, пульс/темп, повторную синхронизацию без дублей и сохранность работы VPN.

Отдельная плата за библиотеку не требуется. Сервер уже оплачен пользователем; достаточность ресурсов и ограничения хостинга не проверены. Не обещать вечную бесплатность сторонних сервисов или подключение без серверной части.
